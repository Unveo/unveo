## 2. check_setup.py

Runs with **any system Python 3.10+** and uses only the stdlib, so it works before anything is installed.

| Check | Pass condition | Fix (`--fix` does it; otherwise the command is printed) |
|---|---|---|
| Python | ≥ 3.10 | Print the OS link: python.org, or `brew install python@3.12`, or `winget install Python.Python.3.12` |
| venv | `~/.unveo/venv` exists and its Python runs | `python -m venv ~/.unveo/venv` |
| Packages | `requirements.txt` versions import in the venv | `<PY> -m pip install -r <SKILL_DIR>/requirements.txt` |
| Chromium | Playwright can launch headless Chromium | `<PY> -m playwright install chromium` (Linux also needs `--with-deps`, which can ask for sudo, so we print it rather than run it) |
| ffmpeg | `imageio_ffmpeg.get_ffmpeg_exe()` runs `-version` | Reinstall imageio-ffmpeg |
| git | `git --version` (only when cloning) | Print the install link |
| Disk | ≥ 3 GB free in the project folder | Warn only |
| Network | `speech.platform.bing.com` is reachable (for edge-tts) | Warn: "Offline: Kokoro will be used" |
| Kokoro (optional) | model files present, if `--with-kokoro` | Download into `~/.unveo/models/kokoro` |

Output JSON: `{"ok": true, "py": "/Users/x/.unveo/venv/bin/python", "skill_dir": "…", "versions": {…}, "warnings": […]}`.

**requirements.txt** (compatible ranges; the tested versions are listed in the file's header comment):
```
playwright>=1.55,<2
imageio-ffmpeg>=0.6,<1
numpy>=1.26,<3
pillow>=10,<13
edge-tts>=7,<8
```
Kokoro and its dependencies sit in a separate `requirements-kokoro.txt`, installed only with `--with-kokoro` or on the first automatic fallback.
> M0 result: `kokoro-onnx` plus the int8 model (92 MB, plus 28 MB of voices). No PyTorch. Hindi and English voices both work.

## 3. The film template (`templates/film/`)

When Phase 3 starts, `templates/film/` is copied to `unveo-out/film/` (only once; the agent edits data files, never the templates).

**How it works**
- `index.html` loads `palette.css`, `core.js` (vendored), `film.js`, all of `scenes/*.js`, and `timeline.js`. `timeline.js` is generated by `plan_timeline.py` as `window.TIMELINE = {...}` with the scene data embedded, so there's no fetch and no CORS problem.
- URL parameters: `?scene=s06` renders one scene in its own local time (0 to `dur_s`); with no parameter, the whole timeline plays (preview). `&w=960&h=540` sets the draft size.
- `film.js` exposes `window.seek(t)`: it finds the scene, computes the local time, and calls `SCENES[template].draw(localT, data, root)`. It sets `window.ready = true` once `document.fonts.ready` resolves and images load.
- **Scene module contract:**
  ```js
  UNVEO.scene('explainer-formula-breakdown', {
    build(root, data, palette) { /* create DOM once */ },
    draw(t, data) { /* set every style from t only */ }
  });
  ```
- **seek(t) rules** (kept from upstream): every visual property is a pure function of `t`; no CSS transitions or animations, no `setTimeout`, no state carried between frames; springs use the closed form `step(tau, f, z)`; easings come from `core.js`. Every layer has a `z-index`.
- **Preview controls** (for the user opening `film/index.html` in a browser): Space = play/pause, ←/→ = step one frame, R = restart, a time readout. Playback uses requestAnimationFrame to drive `seek()`; the render never uses it.

**Templates in v1**

| Template | Data fields | Notes |
|---|---|---|
| `title` | `title`, `event`, `team` | 2.5 s, no voice; the logo is the project's favicon or logo if found |
| `context` | `headline`, `points[≤3]`, `stat` (value + label + source) | kinetic text and icons |
| `problem` | `headline`, `pains[≤3]`, `stat` | "before" state, muted then accented |
| `product-intro` | `name`, `one_liner`, `screenshot` (`capture/probe.png`) | the screenshot zooms into the first capture shot |
| `explainer-*` (5) | see [07](07-EXPLAINERS-SPEC.md) | |
| `close` | `impact_line`, `links[]`, `extra_line`, `title` | links typeset exactly from brief.json; no QR code in v1 |
| `placeholder` | `shot_id`, `what_to_record` | for missing clips |

**Fonts:** Geist (body), Geist Mono (field names and numbers) and Instrument Serif (accent headlines), all under the OFL licence and bundled in `assets/fonts/`. No network fonts at render time.

## 4. Palettes

Tokens (CSS variables): `--bg`, `--surface`, `--ink`, `--muted`, `--accent`, `--accent2`, `--good`, `--bad`.

| Name | bg | ink | accent | accent2 | Feel |
|---|---|---|---|---|---|
| `project` | extracted | extracted | extracted | extracted | the app's own colours |
| `ink-lime` | `#0b0b0c` | `#f5f5f2` | `#cdf24f` | `#38bdf8` | dark, techy |
| `paper-indigo` | `#f7f7f5` | `#0f172a` | `#4f46e5` | `#f97316` | light, clean |
| `civic-saffron` | `#fffaf2` | `#1f2937` | `#f59e0b` | `#047857` | public sector, India |
| `ocean-slate` | `#0f172a` | `#e2e8f0` | `#38bdf8` | `#a78bfa` | calm, data |
| `midnight-violet` | `#0c0a1d` | `#ede9fe` | `#a78bfa` | `#f472b6` | AI and consumer |

**Extracting `project`:**
1. Take `palette_candidates` from repo_scan.json, ranked by role names (primary, accent, background) and then by frequency.
2. Pick bg from the background token, or from the dominant colour of `capture/probe.png` if there isn't one.
3. Fill `muted`, `good` and `bad` from defaults if they're missing.

**Contrast rule:** ink on bg must be ≥ 7:1 and accent on bg ≥ 3:1 (WCAG). If not, adjust lightness until it passes. `render palettes` draws all 6 as swatches with a sample headline, numbered 1–6.

## 5. Render modes

| Mode | Size | Samples per frame | Use |
|---|---|---|---|
| stills | 1920×1080 | 1 | Checkpoint C sheet (`stills/sheet.png`, a 3-column grid with time labels) |
| draft | 960×540 | 1 | quick timing check, `draft.mp4` |
| final | 1920×1080 | 3 subframes spread over half a frame (180° shutter), averaged | the deliverable |

- One Chromium per chunk. Chunks = `min(4, cpu_count // 2)`, at least 1. Each chunk takes a contiguous frame range of the animated scenes.
- Capture hygiene (from upstream): wait for `window.ready` and `document.fonts.ready`; pause `document.getAnimations()`; after each `seek(t)`, wait 2 requestAnimationFrames before the screenshot.
- Frames are piped as JPEG (quality 95) to ffmpeg over stdin (`image2pipe`), with no temporary folder. This is the method measured in M0.
- **Encode** (every segment and the final):
  `-c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p -vf "scale=in_range=pc:out_range=tv:out_color_matrix=bt709" -color_range tv -colorspace bt709 -color_primaries bt709 -color_trc bt709 -r 30 -movflags +faststart`. Audio in the final: `-c:a aac -b:a 192k -ar 48000`.
- **pops:** the mean absolute difference between consecutive frames (downscaled to 320×180). A frame is a pop if its difference is more than 3× both neighbours' and above a floor. Scene boundaries from timeline.json are allowed and reported separately.
- **estimate:** time 10 frames during stills, then `frames × samples × ms_per_capture / chunks`. Printed before the final render: "About 6 minutes."
  > M0 result (10-core Apple silicon Mac): a 10 s two-scene film at 1080p, 30 fps and 3 subframes took 45 s in 1 chunk and 13 s in 4 chunks, about 50 ms per capture. That makes a 2-minute video about 1–3 minutes of render, because most product scenes are recordings and not rendered. Windows timing comes in M7.

## 6. Vendored engine (`scripts/engine/`)

| Upstream file (howseen-ai/claude-motion-design) | Ours | What we change |
|---|---|---|
| `skill/motion-design/scripts/render_template.py` | `engine/render_core.py` | 30 fps, per-scene rendering, chunking, PNG over stdin, no personal paths |
| `skill/motion-design/scripts/audio_template.py` | `engine/audio_core.py` | keep loudnorm and peak placement; drop Mixkit |
| `skill/motion-design/scripts/remake/core.js` | `engine/core.js` | keep easings, springs and helpers; drop the frame-table bits we don't use |

`engine/UPSTREAM.md` records the repo URL, the pinned commit SHA, the date and a line per change. The MIT notice goes in the repo's `NOTICE`. To pull an upstream fix, diff the pinned SHA against the new one and apply by hand.
